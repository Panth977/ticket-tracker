Roadmap

The build is ordered so that each phase ships something usable and the next phase only adds to it. Sizes assume two full-stack developers. They show relative size and are not promises.

Phase 0 · Foundations — ~2 weeks

  • Monorepo (apps/web, functions, packages/shared), pnpm, TypeScript strict, ESLint and Prettier
  • Firebase projects for dev (emulators), staging and prod. CI with typecheck, unit tests, rules tests, and deploy on merge.
  • The api function skeleton: Hono, the user middleware, command() with zod, idempotency by clientId
  • SvelteKit shell: sign-in (Google and email link), Shell, and the live-query store pattern
  • can() with its test table, and the rules test harness

Exit: a signed-in person sees an empty sidebar on staging. A rules test fails the build when it should.

Phase 1 · A tracker you can use — ~5 weeks

  • Open sign-up, the Welcome screen (profile picture, display name, time zone); boards with app-wide keys; invites to a board by email with a role (sent through Resend), accept and decline, People & roles
  • Boards: create from a template, key, stages with categories, priorities, tags, a role per person on each board
  • Tickets: create with a key from allocateKey, update, drag with a rank, archive, cancel and restore, delete behind an opt-in
  • Views: kanban and table only, with a fixed filter bar (not saved yet)
  • Ticket drawer: fields, description (TipTap), activity
  • Backups before real data: a daily scheduled Firestore export to a bucket, kept 30 days, plus one rehearsed restore
  • The sidebar as the whole navigation (boards with their views, People, Settings; the Account menu)
  • My Work, due dates, Quick add

Exit: the team moves off TeamTrack for one real board, and two people dragging cards see each other live.

Phase 2 · Conversation and notifications — ~4 weeks

  • The thread: messages, @ mentions, # refs (Typesense goes live here), attachments with thumbnails, pins, quote-reply, reactions, edit and delete, unread counts, "seen by"
  • notify: inbox and bell, board preferences (TeamTrack's four modes plus events and stages), watch
  • deliver: FCM web push and email, reply-by-email into the thread, digest, quiet hours
  • deadlineSweep (due soon and overdue), commitments
  • Presence and typing

Exit: a mention reaches a phone as a push within 5 seconds, and replying to the email lands in the thread.

Phase 3 · Make it yours — ~4 weeks

  • Custom fields: all types except formula, with required fields and stage requires
  • Saved views, personal and shared: the filter builder, group by any field, swimlanes, column layout
  • Calendar and a real timeline with start and due dates, dragging, and blocks arrows; ticket links
  • Links (blocks / relates / duplicates) and "Referenced by", with the ⛔ blocked badge and timeline arrows; bulk actions
  • ⌘K palette, keyboard map; board templates Blank, Kanban and Bug tracker, and copying an existing board for anything else
  • Account: 2FA, sessions, export, delete

Phase 4 · The platform — ~4 weeks

  • REST /v1 with OpenAPI, API keys and bot members, rate limits
  • Webhooks with signing, retries and a delivery log
  • OAuth 2.1 server with dynamic registration and a consent screen
  • MCP server: the tools, resources and prompts, tested in Claude and at least one other client
  • Intake: the website widget (porting tt.ts) and email-to-board

Exit: "Claude, what's overdue on ENG, and split ENG-42 into three linked tickets" works end to end, and the thread shows it came through MCP.

Phase 5 · Channels and integrations — ~3 weeks, plus Meta approval lead time

  • WhatsApp: number linking by OTP, templates submitted at the start of phase 3 (approval takes days to weeks), buttons, inbound replies
  • GitHub app: keys in branches and PRs, move on merge
  • Slack: board activity to a channel, link unfurls
  • ICS calendar feed

Phase 6 · Hardening and scale — ongoing

  • App Check, abuse limits, audit export, malware scanning of attachments
  • Large-board mode (views through Typesense), load test of 50 people on one board
  • Formula fields, automations ("when moved to QA, assign @qa"), recurring tickets
  • Phone: the sidebar as a ☰ drawer, one-column board and table, a full-screen ticket drawer, shipped as a PWA. A native app only if iOS push forces it.

Migrating from TeamTrack

A one-off script in tools/migrate-teamtrack, run against Postgres:

TeamTrack→Here
TT_TEAMS (id = name, emails)→not migrated as teams. Every email becomes a board invite, one per board they were on, and its uid is resolved when that person first signs in.
TT_BOARDS owning + viewer teams→expanded to people: owning-team owners → admin, its members → editor, viewer-team members → commenter (or editor where the team had edit), each with their team's move_permissions copied as a personal StageGrant
TICKET_ID CLNT-12→the same key, and nextNumber carried over, so every old reference still resolves
SETTINGS.categories (folders)→a select field named Folder, plus a shared view grouped by it
Device ID, Org, Module, Device stage, issue types→custom fields on those boards; issue type and sub-issue become two select fields
conversations (Markdown)→messages converted to ProseMirror; [@Name](mailto:) resolved to mention nodes; the pinned description becomes ticket.description
ASSIGNED_TEAM_IDS→"Team > email" becomes that person. A whole-team assignment becomes every member of the team at migration time.
attachments (URLs)→copied into Storage under the ticket
NOTIFY_PREFS→prefs/{uid} one-to-one; subscribed becomes watching
reporting (slug, secret)→intakes/{slug}, secret re-hashed, so existing widgets keep working
