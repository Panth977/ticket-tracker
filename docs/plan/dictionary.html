Dictionary

A named set of key → value entries, owned like a bucket and used by boards, artifacts and agents through grants. Panth asked (ORCH-9, 2026-10-16) for a fourth entity beside board, artifact and bucket, and for the key/value Env pairs in every thing's settings to go. A dictionary replaces them: one place for settings, prompts and config, written once and granted to whatever needs it. Values are any JSON (Panth's choice over text only).

A · The thing

  • dictionaries/{d} — { name, description, indicator, ownerUid, owner, ownerKey, ownerHandle, orgGranted?, slug, access, memberUids, boards, artifacts, agents, boardIds, artifactIds, agentIds, stats { entries, bytes }, archivedAt, createdAt, updatedAt } (@tm/shared DictionarySchema). Lives at /{handle}/dictionary/{slug} like everything else (§AC).
  • dictionaries/{d}/content/entries — { entries: [{ k, v }], updatedAt, updatedBy }, one document, in order. v is the value's JSON text: Firestore cannot hold every JSON value (nested arrays), and the text round-trips exactly. Kept apart so the sidebar and the lists, which read the dictionary documents, never load the entries.
  • Limits: 500 entries, 64 KB per value, 512 KB per dictionary, keys of 1–128 [A-Za-z0-9_.:-] not starting with . : -; 100 owned; 50 grants of each kind.
  • Indicator (default 📖) and description like every entity (indicators.html).

B · Who may do what

dictionaryReach() is the one answer, exactly the bucket's rule plus agents:

  • Its people: owner → manage, editor → write, viewer → read. Orgs fan out (§AC).
  • A board grant (read | write) is a ceiling: every member reads; a write grant lets the board's editors and admins (and agents in those roles) write.
  • An agent grant: that agent reads (or writes) it on any board — what the old agent env did.
  • An artifact grant: the page may use it, the viewer's own reach the floor (dictionaryArtifactReach).
  • Archived = read-only for everyone until restored. No reach answers 404, never 403. Granting needs both sides (the dictionary's owner who is also admin of the board / owner of the artifact / owner of the agent); either side may end it. Never an agent.

C · Commands and doors

  • dictionaryCreate · Update · Delete · Share · GrantSet · List · Get · Set; scopes dictionary:read / dictionary:write (in every agent token and in the Full account preset). MCP tools dictionary_*.
  • dictionarySet takes set (null removes; a new key goes last) or replace (the order given); expectedUpdatedAt makes it conditional (409 when the entries changed since that read — the editor's guard).
  • REST: GET /v1/dictionaries, GET /v1/dictionaries/{id}, PATCH /v1/dictionaries/{id}/entries.
  • Rules: its people read both documents straight from Firestore (the app's live listeners); everyone else, and every token, reads through the commands. Every write is a command.

D · In the app

  • Sidebar: dictionaries under their owner, like buckets, with New dictionary in the owner's + menu. The page is the entries editor: one row per key, each value Text or JSON (validated as you type), reorder, filter, Save.
  • Settings: General, People, Subscribers. Board, artifact and agent settings get a Dictionaries section (Subscriptions, lib/access) where Env was.
  • The artifact page has tabs: Website (the page), DB (its Firestore), JSON (its realtime tree), Bucket (buckets granted to it) and Dictionary (dictionaries granted to it). DB and JSON are for its owner and editors.

E · Orchestrators: GET /v1/env

Kept, with the same env field, so the workspaces orch needs no change. It now answers the dictionaries granted to the board, then those granted to the calling agent, each set by name (a later name wins a key); the agent's win over the board's. Archived ones are left out. Only env-style keys ([A-Za-z_][A-Za-z0-9_]*) become variables; a string value as it is, anything else as its JSON text. dictionaries says where each came from.

F · The migration

backend/src/migrate/dictionary.ts (Firebase: scripts/migrate-dictionary.mjs; a VM: backend/lib/migrate/dictionaryCli.js). Every non-empty _env/{kind}:{id} becomes one dictionary "name env" with the same pairs, owned by the thing's owner and granted read where the pairs applied: a board → that board, an artifact → that artifact, an agent → that agent, an org → every board and artifact it owns (they inherited it), a bucket → nothing (nothing read it). The id is derived from the env document, so it is idempotent; the _env document is removed once its dictionary exists. Dry run unless --apply.

G · Not in v1

  • Secrets: entries are plain text to everyone who reaches them, as Env was.
  • Invites by email to someone without an account (like buckets).
  • BackendDriver.dictionary for an artifact's own code (the grant exists; the page reads it in the app's Dictionary tab).
  • History of entries.
